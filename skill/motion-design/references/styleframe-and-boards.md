# 三道關卡：storyboard、styleframe、animatic

業界不是「想一想就開始做」。三個不同的產物管三件不同的事，各自有獨立的客戶簽核。

**跳關卡＝用最貴的階段做最便宜的決定。** 文案改一句零成本，分鏡改一格半天，成片改一版要重生。

| 產物 | 管什麼 | 數量 | 過關問的問題 |
|---|---|---|---|
| **storyboard** | 敘事與節奏 | 60 秒 10–12 格；15 秒 7–9 格 | 這個故事這樣說對不對？ |
| **styleframe** | 畫風與美術 | **2–3 張**（不是每格一張） | 成片會長成這樣，你接受嗎？ |
| **animatic** | 時間與可讀性 | 1 支 | 節奏對不對？字讀得完嗎？ |

順序不能換：**敘事 → 畫風 → 時間**。先定畫風再定敘事，會為了留住漂亮的圖而扭曲故事。

---

## §1 storyboard

管的是**敘事**，不是美術。可以很醜，但資訊要齊。

每一格必須有四樣：

1. **粗略構圖** — 誰在畫面上、在哪、鏡頭多大
2. **對應的旁白句**（有旁白的話）— 逐字，不是摘要
3. **這格的秒數** — 這是後面 animatic 的原料
4. **動態註記** — 誰動、往哪動、什麼進場什麼出場

沒有第 3、4 項的分鏡叫插畫，不叫分鏡。

**畫法**：用 Banaverse 免扣點生圖（`gemini-3-pro-image`），或直接用 HTML 排出審圖板（模板 `assets/board-template.html`）。

**生圖的一致性招數**（實測有效）：
1. 先生 **hero 格**當 style key。
2. 把 hero 的 url 當 `refs`，**平行**生其餘格，每格 prompt 都貼同一段 design world 段落。
3. 排成 3×3 或 4×3 總表，Read 進來用眼睛看。

**GATE A 在 storyboard 之前**（腳本／beat sheet 關），**GATE B 在 storyboard 之後**。

### 分鏡「很漂亮但不像 motion」怎麼救（2026-09-11 實測）

第一版分鏡最常見的失敗是**每格都像插畫海報**：背景畫了完整場景、一格塞 5–8 個道具、字變成配角。修法有四條，一起做才有效：

| 症狀 | 修法 |
|---|---|
| 背景在畫場景 | 改成**整格單色**，換場靠整格換色 |
| 字太小 | 標題吃掉畫面 **40–60%** |
| 道具太多 | 一格 **1–2 個**道具（參考片通常「一個角色 ＋ 一個道具」） |
| 每格各自獨立 | 加一個 **through-line 物件**：每一拍都在、逐拍變化 |

### 反推參考片的四個問題

使用者丟參考片時，先抽縮圖拆成可套用的規格，再談機制：

```bash
ffmpeg -i ref.mp4 -vf "fps=1,scale=480:-1,tile=5x3" -frames:v 1 tiles.jpg
```

Read 進來後回答四題，答案寫進 design sheet 的 Rules 區：

1. **換場怎麼換** — 整格硬切換色？形狀對位？鏡頭運動？
2. **字佔多大** — 標題佔畫面幾成、一格幾句、強調怎麼做（麥克筆刷／底線／變色）。
3. **畫面上有幾個東西** — 角色幾個、道具幾個。
4. **有沒有 through-line** — 哪個物件每一拍都在、逐拍變化。

反推完**直接列一張「舊版 vs 新版」差異表**（版面／換場／背景／角色／道具／強調／長度）給使用者看，比口頭解釋有效。

## §2 styleframe

管的是**畫風**。這是整條產線最被誤解的一步：多數人以為要每格一張，其實只要 2–3 張。

### 幾張

- **第一張**：hero moment。挑整支片裡承載識別的那一刻。
- **第二張（必要）**：一個**對比情境**——忙 vs 空、亮 vs 暗、寬 vs 微距。用來證明這套語言撐得住不同條件。
- **第三張（選配）**：極端條件測試（最多元素的那格、或最暗的那格）。

> 一張漂亮的 frame 只證明一個瞬間，兩張才證明一套語言。

**長片的算法是「看起來變了幾次」，不是「有幾格」。** 一支 3 分鐘的片如果只有兩種視覺段落，就只要兩張。**如果覺得每格都需要一張 styleframe，那是美術方向還沒定案**，不是片子複雜。

### 驗收標準（只有一條）

> 一個從沒跟客戶講過話的動畫師，打開這張圖，能不用問就知道成片該是什麼感覺嗎？

做不到就是還沒定案，不要拿去給客戶看。

### 必須是已決定的事

| 項目 | 意思 |
|---|---|
| **顏色與光** | 實際色票在最終光線條件下的相互關係，不是色票條 |
| **字體** | 真字體、生產尺寸、真實文案。**不准 placeholder** |
| **構圖與層級** | 不靠動態就能帶著眼睛走 |
| **材質與景深** | 顆粒、模糊、光暈、材質質感——讓平面的圖有重量 |

### 最重要的一條

**styleframe 必須在靜止狀態就成立。**

一張需要靠動態來解釋「為什麼構圖這麼空／這麼擠」的 styleframe，是警訊不是捷徑。動態不會救弱構圖，只會讓弱構圖動起來。

### 簽核的意義

客戶簽了 styleframe＝簽了整套視覺語言。從那一刻起工作性質改變：從「開放式探索」變成「執行一個已同意的目標」。這是你能擺脫無限修改的唯一機制。

### styleframe ≠ design sheet

兩者都要做，分工不同：

| | styleframe | design sheet |
|---|---|---|
| 是什麼 | 成片的一格長什麼樣 | 元件與字形的標本頁 |
| 給誰看 | 客戶簽核 | **餵給模型當 `image_references`** |
| 長相 | 完整構圖、有情境 | 素淨背景、元件孤立、字放很大 |
| 模板 | 無（就是生成的圖） | `assets/design-sheet-template.html` |

**design sheet 一定用 HTML 做，不要用 AI 生。** 字體外形會被完整保留，這是字能活下來的唯一原因。

prompt 裡引用它的固定句型（不可簡化）：

> Image 1 is a graphic-design system reference ONLY — copy its letterform shapes and its element designs exactly; never copy its layout or background. From Image 1: TYPE A = …, PILL = …, BADGE = …

## §3 animatic

管的是**時間**。這一關會抓出最貴的錯：旁白唸不完、字來不及讀、beat 排太滿。

做法（免生成、幾分鐘就好）：

```bash
# frames.txt
# file 'shot1.png'
# duration 2.0
# file 'shot2.png'
# duration 1.8
# ...
# file 'shot9.png'      ← 最後一張要重複寫一次，否則 concat 會吃掉它
# duration 1.5
# file 'shot9.png'

ffmpeg -f concat -safe 0 -i frames.txt -i scratch_vo.mp3 \
  -vf "scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:-1:-1" \
  -shortest -pix_fmt yuv420p -r 30 animatic.mp4
```

有旁白的片，**scratch 旁白先於 animatic**。用 TTS 粗配一版量真實時長：

```bash
cd "$VIDEO_EDITOR_ROOT/kit" &&   # 作品 02 剪輯工具鏈；沒有的話用任何 TTS 粗配即可
 /usr/bin/python3 -m src.narrator.narrate \
  --text-file script.txt -o scratch_vo.mp3
```

**旁白時長決定 beat 數，不是反過來。** 先量出旁白多長，再決定畫面切幾段。

### animatic 要驗的四件事

- [ ] 旁白唸得完嗎（有沒有哪句被切掉）
- [ ] 每句畫面文字落定後停 ≥ 0.5 秒嗎
- [ ] beat 有沒有排太滿（全片都在動＝觀眾沒有呼吸點）
- [ ] 有沒有一個純停住的空拍（15 秒的片至少要一個）

### 為什麼這關不能跳

生成式影片的秒數是**買來的**。animatic 花 0 元就能發現「這支片其實需要 20 秒」，生成階段發現就是多付一段的錢加等待。

**GATE C 過了才寫 prompt。**

## §4 三關的修改輪次

業界標準：**每一關 2–3 輪**，兩輪內含在報價裡。

| 關卡 | 什麼算修改 | 什麼算變更範圍（要加價） |
|---|---|---|
| GATE A（腳本） | 改字、換順序 | 換訴求、換受眾 |
| GATE B（分鏡） | 改構圖、加減一格 | 改敘事結構、改秒數 |
| GATE C（animatic） | 調秒數、調停留 | 加 beat、加鏡頭 |
| 成片 | 換顏色、改錯字 | 換畫風、重寫敘事 |

**每個 GATE 要拿到明確的「這版可以」再往下。** 客戶第三輪還在改大方向＝前面的 GATE 沒真的過。

報價與收費細節見 `business.md`。
